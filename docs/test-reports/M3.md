## What was ported (DD-8; cited to analysis §05/§06 and tt-kmd source)

- **MAP/UNMAP** (Windows extensions replacing mmap): opaque-token decode parity
  with `tenstorrent_mmap` (BAR UC/WC regions, TLB UC/WC, DMA-buffer slots). User
  mappings built from **physical-page MDLs** + `MmMapLockedPagesSpecifyCache`
  (UC/WC for device memory, cached for DMA buffers), served from
  EvtIoInCallerContext for correct process context.
- **TLB pool**: 210-window bitmap, exact-size allocation (no round-up), single-
  owner model, id 201 kernel-reserved, 4G count clamped by BAR4; FREE_TLB
  EPERM/EBUSY parity; registers not cleared on free (upstream parity).
- **DMA buffers**: WDFDMAENABLER + WdfCommonBuffer, validation order and limits
  per memory.c:439-458; FREE_DMA_BUF stub -EINVAL; iATU-before-free cleanup.
- **Outbound iATU allocator**: 16-region first-fit (top-down/bottom-up),
  noc_pcie_offset + base, 1 TiB cap, register programming per blackhole.c:755-788.
- **PIN_PAGES/UNPIN_PAGES**: MmProbeAndLockPages + PFN-contiguity (direct/no-IOMMU
  path); READ_ONLY -> STATUS_NOT_SUPPORTED, discontiguous -> -EINVAL, dup-pin
  collision, exact-match unpin; MmUnlockPages dirties write-locked pages.
- Full cleanup-on-close: mappings, pinnings, DMA buffers (iATU first), TLB windows.

## Bugs found and fixed during M3

1. **Physical-MDL bug (driver):** initial MAP used `MmBuildMdlForNonPagedPool` on
   an `MmMapIoSpaceEx` VA — that routine only works for nonpaged-pool VAs and
   produced wrong PFNs for device BAR / common-buffer memory (user-mode
   0xC0000005). Fixed to build the MDL from physical page frames directly (the
   WDK mapmem idiom) and map that. This is the correct way to expose device/IO
   memory to user mode.
2. **ttsim model gap (test double, not the port):** stock ttsim fatals on the
   Blackhole strided-TLB config registers (BAR0 0x1FC009D8+) that tt-kmd clears
   for windows < 32 (blackhole.c:192-196). Linux tt-kmd would crash it
   identically. Patched libttsim to accept those writes; the driver keeps exact
   upstream behavior.
3. **Test bug (not the port):** the pin test declared the extended 16-byte out
   in a 32-byte buffer that only has 8 bytes of out space; the driver correctly
   faulted (Linux `clear_user` parity). Fixed the test to size the buffer.
