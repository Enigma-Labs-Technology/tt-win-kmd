# M4 Test Report — Reset, Hotplug, Lifecycle

**Date:** 2026-07-07 · **Status: ACCEPTED**

## Environment

- Guest: Windows 11 (26200) under local QEMU 8.2.2/KVM with `ttsim-bh`
  (heartbeat + strided-TLB patched libttsim). QEMU glue rebuilt to model the chip
  reset: a write of the DWC interface-timer register with FORCE_PENDING clears
  the PCI_COMMAND parity marker, so POST_RESET's "marker cleared" check succeeds
  (ttsim has no config-space reset path). Driver Verifier active throughout with
  Special pool / Force IRQL / Pool tracking / I/O / Deadlock / DMA checking.
- Build: EWDK, /W4+WX + Code Analysis clean (incl. the new reset.c).

## What was ported (DD-9; cited to analysis §11 and tt-kmd source)

- **RESET_DEVICE** with all seven flavors (chardev.c:200-310): dispatch by flag
  value with -EINVAL default; `out.result = !ok` (a failed reset still succeeds
  the ioctl); the destructive flavors bump the generation, zap mappings, and set
  `needs_hw_init` exactly as upstream (RESTORE_STATE / RESET_PCIE_LINK /
  CONFIG_WRITE / USER_RESET / ASIC_RESET / ASIC_DMC_RESET / POST_RESET).
- **reset_rwsem → ERESOURCE**: RESET_DEVICE exclusive, every other ioctl and
  MAP/UNMAP/PIN/UNPIN and file cleanup shared; exclusive acquire drains in-flight
  operations before the reset proceeds.
- **Gen-bump fd invalidation** (bump_reset_gen): the resetter's handle is carried
  forward; every other open handle fails the gate with STATUS_DEVICE_REMOVED
  permanently.
- **needs_hw_init reset window**: only GET_DEVICE_INFO / GET_DRIVER_INFO /
  RESET_DEVICE until POST_RESET clears it.
- **VMA-zap equivalent**: tracked user mappings (BAR/TLB) unmapped device-wide on
  destructive reset — same-process in-context, cross-process via
  KeStackAttachProcess; DMA-buffer maps left alone (Linux parity). After unmap
  the stale user VA faults.
- Config-space primitives (marker set/check, pcie_timer_interrupt) via
  BUS_INTERFACE_STANDARD; BH `blackhole_reset` (ASIC config-write trigger,
  DMC via ARC TRIGGER_RESET message) and `init_hardware` re-run.
- **Surprise removal**: EvtDeviceSurpriseRemoval sets `Detached` and zaps
  mappings; the gate then returns STATUS_DEVICE_REMOVED for all operations.

## Acceptance evidence

**ttinfo.exe reset lifecycle (2 devices, 0 failures, exit 0):**
- Invalid flag (99) → ERROR_INVALID_PARAMETER.
- ASIC_RESET issued from a *fresh* handle while a worker handle holds a live TLB
  mapping (the tt-umd/tools/reset.c pattern): `result=0` (success).
- **Stale worker handle → gle 1617 (ERROR_DEVICE_REMOVED)** on every ioctl — the
  spec's explicit STATUS_DEVICE_REMOVED criterion.
- **Stale mapping access faults** (SEH-caught) — the zapped mapping no longer
  dangles.
- Reset window: resetter's GET_DEVICE_INFO allowed; QUERY_MAPPINGS rejected.
- POST_RESET `result=0` — marker cleared by the glue, window closed, device
  usable again.

**Reset storm (`--storm 2000`)**: 2,000 iterations of {worker maps a TLB window;
fresh handle issues ASIC_RESET or CONFIG_WRITE; stale worker ioctl; POST_RESET;
close both} — **PASS**, exit 0.

**Surprise removal**: 6 `pnputil` disable/enable cycles of the PCI device
(removal with active mappings + re-enumeration) — device returns to **OK** each
time, no crash.

**Verifier / health after all of the above**: `Current Pool Allocations: 0 / 0`
(no leaks across the storm + hotplug), **zero** WER/bugcheck events. All the
required Verifier options (special pool, IRQL, pool tracking, I/O, deadlock, DMA)
were active — no violations.

## Deviations / open items (OQ-5)

- **RESET_PCIE_LINK secondary-bus reset** cannot be issued from a KMDF function
  driver (it targets the upstream bridge); it maps to the PCI reset interface
  where present and is otherwise a documented rig no-op (mappings are still
  zapped). Real-hardware bring-up should wire `GUID_DEVICE_RESET_INTERFACE_STANDARD`.
- **Full config save/restore and the DBI Max-Payload-Size snapshot** are
  real-hardware refinements; on the rig the fake reset preserves BARs, so
  `safe_pci_restore_state` reduces to a device-present check. Both are tracked as
  OQ-5 for silicon bring-up.
