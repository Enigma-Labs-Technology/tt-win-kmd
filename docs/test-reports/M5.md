**Date:** 2026-07-07 · **Status: ACCEPTED**

## Environment

- Guest: Windows 11 (26200) under local QEMU 8.2.2/KVM with `ttsim-bh`. Driver

## What was ported (DD-10; cited to analysis §04, §10 and tt-kmd source)

- **LOCK_CTL** (chardev.c:371-430): 64 resource locks via a device 64-bit held
  bitmap + per-handle held bitmap (global-set-while-local-set invariant).
  ACQUIRE / RELEASE / TEST are immediate bit ops with exact value semantics.
  **ACQUIRE_BLOCKING** that can't win is forwarded to a manual WDFQUEUE — WDF
  makes it cancellable. Wakers (RELEASE, handle cleanup, reset gen-bump,
  surprise removal) drain the queue and retry each waiter; winners complete
  value=1, stale-gen/detached waiters complete STATUS_DEVICE_REMOVED, losers are
  re-queued. Locks survive reset; released only at handle close.
- **SET_POWER_STATE** (chardev.c:478-589): each handle stores a contribution;
  create (legacy default: all flags on except MAX_AI_CLK), close, and every
  SET re-aggregate across all live handles — flags OR'd with the "unspecified
  defaults ON" rule, settings by max, stale-gen handles skipped — and send the
  aggregate to firmware as an ARC POWER_SETTING (0x21) message.
- **Telemetry query** (Windows-extension IOCTL_TENSTORRENT_QUERY_TELEMETRY):
  hwmon-equivalent, returning scaled sensor values with a present-mask
  (is_visible parity). Scaling is byte-identical to the Linux hwmon ABI
  (m°C / mV / mA / µW / RPM) plus the tt_* sysfs values.

## Acceptance evidence

**ttinfo.exe (2 devices, 0 failures, exit 0):**
- **Telemetry**: aiclk = 1000 MHz (tag 14, MHz as-is), serial = 0x40000000001
  (tags 1:2 = P150 board id high 0x400 : low 0x1), heartbeat present, fw_bundle
  = 0x12050000 (v18.5) — all matching ttsim's emulated CMFW table with correct
  units/packing.
- **Locks**: acquire→value1, test→3 (held-by-us|held-by-any), free→0,
  release→1, double-release→0, cross-handle contention→0.
- **Blocking acquire woke on release**: a background thread's ACQUIRE_BLOCKING
  on a held lock stayed pended (not completed after 500 ms), then completed with
  value=1 the moment the holder released — the cancellable-pended-IRP mechanic.
- **Blocking acquire cancelled**: a second pended blocking acquire was cancelled
  mid-wait via `CancelSynchronousIo` → returned gle 995 (ERROR_OPERATION_ABORTED,
  STATUS_CANCELLED), replacing Linux -ERESTARTSYS.
- **Power aggregation**: two handles set MAX_AI_CLK+setting[0]=100 and
  TENSIX_ENABLE+setting[0]=250; the driver's aggregate (read back via the debug
  ioctl) = flags 0x7ff5 (both requested bits OR'd in, plus unspecified-default-ON
  bits) and setting[0] = 250 (max) — the multi-client domain aggregation.
- All M2/M3/M4 checks re-ran green (no regressions).

**Stress**: 30 consecutive full-suite runs (each exercising blocking-acquire
wakeup + cancellation + power aggregation + reset lifecycle) under Verifier —
all exit 0; `Current Pool Allocations: 0 / 0`; **zero** bugchecks.

## Deviations / notes

- The blocking-acquire wait is implemented entirely as a pended request outside
  any lock, so a blocked waiter can never hold up reset/removal — this is
  cleaner than Linux's "drop reset_rwsem during the wait" discipline and
  satisfies the spec's cancellation requirement directly.
- WH/BH hwmon label naming differences (asic_temp vs asic1_temp) are a
  naming-only concern deferred until a Wormhole device exists.
