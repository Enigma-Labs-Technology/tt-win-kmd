# M6 Test Report — Compatibility Shim and Handoff

**Date:** 2026-07-07 · **Status: ACCEPTED**

## Deliverables

- **`ttwin_compat`** (`src/ttwin_compat/`): a user-mode static library exposing
  POSIX-shaped `tt_open` / `tt_ioctl` / `tt_mmap` / `tt_munmap` / `tt_close` /
  `tt_enumerate` over the ttkmd driver. The `TENSTORRENT_IOCTL_*` request
  constants and every argument struct are unchanged from `tt-kmd/ioctl.h`
  (shared `src/include/ttkmd_ioctl.h`, static_asserted), so tt-umd ports by
  swapping only the five syscalls.
- **`docs/tt-umd-porting-notes.md`**: every OS-touching call site in tt-umd's
  device-access layer (`pci_device.cpp`, `tt_kmd_lib.c`) with its shim
  replacement, drawn from the verified §13 inventory; plus the behavioral notes
  (PIN_PAGES contiguity, O_APPEND power mode, mmap-survives-close, reset
  invalidation) and the out-of-scope items (hugepages, hwloc/NUMA, MAP_PEER_BAR,
  EXPORT_TLB_DMABUF).
- **`ttconform`** (`src/tests/ttconform/`): a conformance suite that exercises
  every implemented IOCTL and mmap **exclusively through the shim**.

## Acceptance evidence

`ttconform.exe` in the ttsim VM (0 failures, exit 0), all through `ttwin_compat`:
- `tt_enumerate` → 2 devices; per-device `tt_open` + `tt_ioctl(GET_DRIVER_INFO,
  GET_DEVICE_INFO)` + `tt_close`; identified the Blackhole (`1e52:b140`).
- `tt_ioctl(QUERY_MAPPINGS)` with a 6-entry buffer (the shim's variable-size
  path keyed off `in.output_mapping_count`) → BAR0 512 MiB.
- `tt_ioctl(ALLOCATE_TLB → CONFIGURE_TLB)` then `tt_mmap` of the window →
  **user VA reads simulated CSM (version 1)** → `tt_munmap` → `tt_ioctl(FREE_TLB)`.
- `tt_ioctl(ALLOCATE_DMA_BUF)` → `tt_mmap` → write/read-back; then
  **`tt_close` with the view still mapped, access still valid, then `tt_munmap`**
  — the mmap-survives-close semantics tt-umd's destructor (pci_device.cpp:572-601)
  relies on, emulated by the shim holding the driver handle open until the last
  unmap.
- `tt_ioctl(LOCK_CTL acquire/release)` and `tt_ioctl(SET_POWER_STATE)` incl. a
  negative case (bad argsz → -1).

## Notes

- The shim maps the device id (the Linux `N` in `/dev/tenstorrent/N`) to the
  ttkmd device-interface reference-string ordinal `TT<N>` (DD-2), so tt-umd's
  integer-id identity model ports unchanged.
- Build integration: `build.ps1`/`build.sh` build and ship `ttwin_compat.lib`
  and `ttconform.exe` at the same /W4+WX bar as the rest of the tree.

## Definition-of-done coverage

Every IOCTL is exercised at least once positive; negative cases exist across the
suite (bad argsz here; the ttinfo suite adds undersized-buffer, wrong-size,
out-of-range, foreign-owner, unaligned, and unsupported-flag cases per milestone).
The parity matrix shows every functionally-portable IOCTL at `tested`
(MAP_PEER_BAR / EXPORT_TLB_DMABUF deferred by design — rig cannot host a second
device; no Windows dma-buf equivalent).
