## Acceptance evidence

1. **ttsim glue smoke (host)**: QMP `query-pci` shows `1e52:b140`, BAR0 512 MiB /
   BAR2 1 MiB / BAR4 4 GiB (64-bit), identity mirrored from libttsim at realize.
2. **Guest enumeration**: `PCI\VEN_1E52&DEV_B140&SUBSYS_00000000&REV_00` with
   class `CC_1200xx` (Processing Accelerator, mirrored from ttsim);
   `pnputil /add-driver ttkmd.inf /install` bound it; device status **OK**
   (i.e. `TtMapBlackholeBars` — TLB regs / kernel TLB / NOC2AXI sub-ranges +
   whole BAR2 via `MmMapIoSpaceEx` — succeeded against the ttsim BARs).
   Soft device `ROOT\TTKMD_SOFT` also OK (`load: 2` in `verifier /query`).
3. **ttinfo.exe conformance (in guest, exit 0, 0 failures, 2 devices)**:
   - Interfaces enumerated via `GUID_DEVINTERFACE_TENSTORRENT` with reference
     strings (`TT0` PCI, `TT2` soft).
   - GET_DRIVER_INFO: ioctl-abi 2, version 2.10.1; `Information` and
     `out.output_size_bytes` exact.
   - GET_DEVICE_INFO: `1e52:b140`, bdf `00:04.0` (matches the QEMU slot),
     domain 0, `max_dma_buf_size_log2` 28; truncation case (declared=4 →
     Information=8, field reports kernel size 20) and oversize-declare
     (→ ERROR_NOACCESS, -EFAULT parity) both pass.
   - QUERY_MAPPINGS with counts 0/2/6/16: six entries (UC/WC per BAR 0/2/4),
     tokens `(0..5)<<36`, sizes 512M/512M/1M/1M/4G/4G; zero-fill of extra
     declared slots verified; soft device correctly reports zero valid entries.
   - Negative: GET_HARVESTING → ERROR_INVALID_PARAMETER (Linux default -EINVAL
     parity); input buffer shorter than `sizeof(in)` → ERROR_NOACCESS.
4. **BAR values cross-checked** three ways: ttsim source constants
   (libttsim.cpp:12-22), QMP query-pci, and QUERY_MAPPINGS output — identical.
